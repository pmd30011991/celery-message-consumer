Apply three surgical fixes to `event_consumer/handlers.py`:

**Fix 1 — CONN-01: Handler list reset in _close()**
Add `self.handlers = []` as the LAST line of `_close()`, after the channel close loops. This ensures no stale references survive between stop() and the next start(). Do NOT place it before the loops (would break iteration). Reference: 03-RESEARCH.md Pattern 1.

**Fix 2 — CONN-02: Guard requeue in _on_pool_error finally block**
In `_on_pool_error`, the `finally` block currently has:
```python
if not message.acknowledged:
    message.requeue()
    _logger.critical(...)
```
Wrap `message.requeue()` in try/except Exception:
```python
if not message.acknowledged:
    try:
        message.requeue()
    except Exception:
        _logger.warning(
            "Could not requeue message for '%s' (channel likely closed by reconnect)",
            self.routing_key, exc_info=True
        )
    else:
        _logger.critical(
            "Message for task '%s' unacknowledged after error callback - requeueing.",
            self.routing_key,
        )
```
The _logger.critical moves to the else clause — it should only log when requeue succeeds. Reference: 03-RESEARCH.md Pattern 2.

Also update the warning message in `_on_pool_success` except block to include "(channel likely closed by reconnect)" for consistency.

**Fix 3 — POOL-04: Prefork guard in start()**
After `self.pool = c.pool` and `pool_limit = getattr(self.pool, 'limit', None)`, add:
```python
try:
    from celery.concurrency.asynpool import AsynPool
    if isinstance(self.pool, AsynPool):
        _logger.warning(
            "AMQPRetryConsumerStep: Prefork pool detected (-P prefork). "
            "Falling back to inline dispatch. "
            "Use -P eventlet or -P gevent for true async dispatch."
        )
        self.pool = None
        pool_limit = None
except ImportError:
    pass
```
Place this BEFORE the prefetch_count resolution line so pool_limit=None feeds into the fallback chain correctly. Reference: 03-RESEARCH.md Pattern 3.
